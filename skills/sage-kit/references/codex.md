# Codex

Use Codex native planning, editing, terminal, worktree, subagent, review, and
GitHub capabilities inside project authority. SAGE-Kit does not require a
command wrapper or framework runtime.

Codex automatically discovers project `AGENTS.md` instructions from the
project root toward the working directory. Use the root bootstrap as the
automatic SAGE-Kit entry: it carries Light work and directs Standard or Heavy,
acceptance, review, corrective, and release work to the complete Skill. When
the installed Skill is available for model invocation, its description permits
that routing without `$sage-kit` in each prompt. Explicit invocation remains an
override and diagnostic path.

`AGENTS.md` is model instruction context, not operating-system containment,
path enforcement, permission proof, or evidence that an action ran.

- Prefer one controller and disjoint subagents for independent work.
- Descendants inherit the same or narrower SAGE boundary, forbidden paths,
  permission ceilings, and human gates. Pass the selected profile with the
  task; do not trigger nested Skill reloads or duplicate review.
- Use project-native focused commands; avoid repeated broad suites.
- Treat terminal access as powerful but not proof of operating-system
  containment.
- Do not install or load unrelated workflow bundles merely because they exist.
- Merge, release, credentials, destructive actions, and human acceptance need
  their own authority.

Codex session state is not project truth. Keep a compact handoff snapshot in
the project's `ACTIVE_CONTEXT`, and refresh machine facts from Git, runtimes,
checks, reviews, and artifacts that own them.
